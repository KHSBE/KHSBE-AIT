# 선택형 일정 전환

## 이번 변경

- 일반 채팅을 제거하고 5단계 선택 화면으로 변경: 여행지/날짜, 동행, 관심사/강도, 선택 숙소/필수 장소, 최종 확인.
- 한국어 안내, 입력 중 임시 저장, 생성 대기/오류/재시도, 모바일 레이아웃.
- 텍스트 요청 대신 검증되는 구조화 DTO. 숙소 미정이면 AI가 숙소를 만들어내지 않음.
- Argon + Maps Grounding으로 후보 탐색 후 Places New로 확인. 확인된 ID만 일정에 채택.
- 영업시간 데이터가 있을 때 시간표 충돌 검사. 정보가 없으면 미확정으로 취급하며 방문 가능성을 보장하지 않음.
- 독립 사용량 장부, 비관적 잠금, 요청 해시/ID 멱등성, 실패 예약 해제, 이전 시도 응답 차단.
- 모든 날짜를 원자적으로 편집하고 서버가 장소 ID를 재검증. 클라이언트 검증 점수 위조 차단.
- 코드 교환/HttpOnly Refresh 회전·폐기, 허용 Origin 검사, Vercel 인증 프록시.
- Spring AI·Redis/벡터·날씨 도구 및 Places 원문 24시간 캐시 제거. 기존 데이터 테이블은 미삭제.

## 로컬 검증 기록

- 백엔드 단위/DB 슬라이스 테스트와 실행 JAR 빌드, 프론트 lint/production build 실행.
- H2 실제 트랜잭션으로 쿼터 경합, 늦은 시도 응답, 전체 날짜 편집 롤백, 타 사용자 차단, 서버 값 우선 저장 검사.
- 인증 코드 단일 사용, Refresh 회전/폐기, 미허용 Origin 차단과 쿠키 속성 검사.
- 샘플 조건으로 데스크톱 1440px/모바일 390px 단계 이동과 가로 잘림 검사. 화면 검증용 API 대체 파일은 제거.
- 실제 1일 생성 테스트는 Places 키 IP 제한으로 차단됨(API_KEY_IP_ADDRESS_BLOCKED). 실제 장소/시간표 품질 검증 성공으로 기록하지 않음.

## 배포 전 필수

1. Render 환경변수 AI_MODEL_PLAN을 gemini-4-argon으로 변경하거나 이전 override 삭제. GOOGLE_CLOUD_LOCATION=global.
2. Google Cloud Places API(New) 활성화 및 서버 키에 Render 서비스의 현재 Outbound IP 범위 허용. 기존 EC2 IP만 허용된 키는 동작하지 않음.
3. 브라우저 키는 별도 키로 Maps JavaScript/Places New 및 프론트 사이트 제한 설정.
4. DB 백업 후 신규 Flyway 적용 확인. 초기 버전은 기존 Hibernate update 병행.
5. 프론트 vercel.json 인증 rewrite와 백엔드를 함께 반영. API/로그인 계약이 바뀌므로 한쪽만 새 버전으로 장기간 운영하지 않음.
6. 재로그인 후 선택→생성→저장→새로고침→편집→삭제·쿼터 테스트.

## 남은 작업

- 실제 Google OAuth 쿠키 프록시와 PostgreSQL 배포 통합 테스트.
- 여러 도시·여행 강도·필수 장소·영업시간 누락 사례의 평가 데이터셋과 비용/지연 측정.
- 실제 이동시간은 미계산. 길찾기는 Google Maps로 연결.
- AI 부분 일정 수정, 사진 중심 상세 화면 개선은 미구현.
- 전체 도메인의 Flyway 전환, 만료 인증 레코드 정리, CSP/XSS 방어 및 부하 테스트.
- Google Maps/Places 콘텐츠 표시·보관 정책을 실제 서비스 사용 방식과 대조.
