# Compass 가성비 배포 실행 가이드 (초보자용)

이 문서는 **"내 컴퓨터를 꺼도 서비스가 계속 열리는 상태"**를 목표로 작성되었습니다.  
구성은 아래처럼 최소 비용으로 갑니다.

- 프론트: Vercel
- 백엔드 + PostgreSQL + Redis: AWS EC2 1대 (Docker Compose)
- 도메인: Cloudflare 또는 Route53
- HTTPS: Caddy

---

## 2. AWS EC2 생성

### 2-1. 인스턴스

- OS: Ubuntu 22.04 LTS
- 타입: `t3.micro` (프리티어 가능 시)
- 스토리지: 20GB 이상 권장

### 2-2. 보안 그룹 (Inbound)

- 22 (SSH)
- 80 (HTTP)
- 443 (HTTPS)

주의: **5432/5433/6379 외부 오픈 금지**

## 5. 배포용 환경변수 작성

EC2의 `KHS-BE` 루트에 `.env` 생성:

```env
# DB/Redis (EC2 내부 Docker 네트워크 기준)
DB_HOST=postgres
DB_PORT=5432
DB_NAME=compass
DB_USERNAME=compass_user
DB_PASSWORD=change_this_password

REDIS_HOST=redis
REDIS_PORT=6379

# OAuth / JWT / AI / Weather
GOOGLE_CLIENT_ID=your_google_client_id
GOOGLE_CLIENT_SECRET=your_google_client_secret
GOOGLE_AI_STUDIO_API_KEY=your_google_ai_studio_key
WEATHER_API_KEY=your_weather_api_key
JWT_SECRET=your_long_random_jwt_secret

# 프론트 연동
CORS_ALLOWED_ORIGINS=https://your-frontend-domain.com
OAUTH2_REDIRECT_URI=https://your-frontend-domain.com/oauth2/redirect
```

## 6. 배포용 Docker Compose 작성

루트에 `docker-compose.prod.yml` 생성:

```yaml
services:
  postgres:
    image: ankane/pgvector:latest
    container_name: compass-db
    environment:
      POSTGRES_DB: compass
      POSTGRES_USER: compass_user
      POSTGRES_PASSWORD: ${DB_PASSWORD}
    volumes:
      - compass_db_data:/var/lib/postgresql/data
    restart: always

  redis:
    image: redis:latest
    container_name: compass-redis
    restart: always

  backend:
    build:
      context: ./backend
    container_name: compass-backend
    env_file:
      - .env
    depends_on:
      - postgres
      - redis
    expose:
      - "8080"
    restart: always

  caddy:
    image: caddy:2
    container_name: compass-caddy
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - backend
    restart: always

volumes:
  compass_db_data:
  caddy_data:
  caddy_config:
```

## 7. Caddy 설정

루트에 `Caddyfile` 생성:

```caddy
api.your-domain.com {
    reverse_proxy backend:8080
}
```

주의:
- `api.your-domain.com`을 실제 API 도메인으로 교체
- DNS가 먼저 연결돼 있어야 인증서 발급이 정상 동작

---

## 8. EC2에서 실행

```bash
docker compose -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.prod.yml ps
docker compose -f docker-compose.prod.yml logs -f backend
```

백엔드 로그에서 `Tomcat started on port(s): 8080` 확인.

---

## 9. 도메인 DNS 연결

도메인 관리 화면에서:

- `A` 레코드
- 호스트: `api`
- 값: EC2 퍼블릭 IP

전파 후 아래 확인:

```bash
nslookup api.your-domain.com
```

## 10. 프론트(Vercel) 배포

## 11. Google OAuth 콘솔 설정

Google Cloud Console > OAuth Client(Web)에서:

- Authorized JavaScript origins: `https://your-frontend-domain.com`
- Authorized redirect URI: `https://api.your-domain.com/login/oauth2/code/google`

또한 EC2 `.env`의 아래 값을 프론트 도메인으로 맞춰야 함:

- `CORS_ALLOWED_ORIGINS=https://your-frontend-domain.com`
- `OAUTH2_REDIRECT_URI=https://your-frontend-domain.com/oauth2/redirect`

## 13. 장애 체크 포인트

- `role "compass_user" does not exist`  
원인: DB 포트/호스트 오설정 또는 다른 Postgres에 연결  
해결: `DB_HOST`, `DB_PORT` 재확인 (`postgres:5432`)

- `Could not resolve placeholder 'JWT_SECRET'`  
원인: `.env` 미적용  
해결: `.env` 존재 확인 + `docker compose ... up -d --build` 재실행

- OAuth 로그인 후 리다이렉트 실패  
원인: Google OAuth 콘솔 URI 불일치  
해결: Redirect URI/Origin 정확히 일치시킬 것
