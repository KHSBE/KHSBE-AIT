# 아키텍처

기준: 2026-11-05 선택형 전환 코드. 배포 적용과 기능 검증 완료를 뜻하지 않습니다.

## 생성 파이프라인

1. 프론트 5단계에서 도시 Place ID, 1~7일 날짜, 동행/인원, 관심사, 여행 강도, 선택 숙소/필수 장소를 수집합니다.
2. 인증 사용자 행을 잠그고 requestId·요청 해시로 중복/충돌을 판정한 뒤 사용 가능 횟수 한 자리를 예약합니다. 외부 호출 중 DB 트랜잭션을 유지하지 않습니다.
3. 서버가 도시·선택 숙소·필수 장소를 Places New로 조회합니다. 국가와 도시 viewport를 기준으로 지역을 제한하고 폐업 정보를 차단합니다. viewport는 행정 경계의 완전한 대체물이 아닙니다.
4. Gemini Maps Grounding의 실제 groundingChunks.maps.placeId를 수집합니다. 모델 본문에서 임의 ID를 추출하지 않습니다. Places-only로 경로 Grounding은 요청하지 않습니다.
5. Grounding의 일시적 혼잡·네트워크·응답 시간 초과는 Places Text Search New로 대체할 수 있습니다. 인증·명시적 할당량 오류는 숨기지 않고 중단합니다. 대체 후보도 같은 국가/지역·영업 상태·품질 검사를 거치며 출처는 PLACES_API로 기록합니다. ID를 Places에서 재조회해 후보를 확인합니다. 후보가 부족한 경우에만 지역 제한 Text Search New로 보충합니다. 실패한 검증을 성공으로 간주하지 않습니다.
6. 확인한 후보와 영업시간 periods를 JSON 스키마 기반 생성 요청에 전달합니다. 중복 요일 설명 문구는 AI 입력에서 빼고 서버 검증에는 전체 원본 시간을 유지합니다. 서버가 이름·좌표를 후보에서 채우며 AI가 임의로 제공한 값을 저장하지 않습니다.
7. 날짜/일차, 장소 수, 중복 ID, 필수 장소, 체류시간, 시간 중복, 제공된 영업시간, 분류를 검사합니다. 실패하면 오류 이유를 전달해 한 번 재생성합니다.
8. 일정과 출처를 저장하고 사용량을 함께 확정합니다. 저장 실패는 모두 롤백합니다. 생성 실패는 예약을 해제합니다.

모델 기본값은 gemini-4-argon, 위치 global입니다. 구형 Spring AI 어댑터 대신 Google Credentials + RestClient로 공식 generateContent REST 계약만 구현했습니다. 모델 변경 시 Grounding과 thinkingConfig 지원을 다시 확인해야 합니다.

## 사용량과 재시도

- KST 날짜별 plan_usage_days가 성공 횟수의 기준입니다. 일정 삭제로 사용량이 줄지 않습니다.
- 사용자 비관적 잠금으로 마지막 횟수의 동시 선점을 방지합니다. 사용자당 진행 중 생성은 한 건입니다.
- plan_generations에는 요청 UUID, 입력 해시, 상태, 만료, 시도 번호, 결과 ID가 남습니다.
- 동일 조건/ID의 성공 재전송은 같은 결과를 반환합니다. 조건을 바꾼 ID 재사용은 409입니다.
- 예약은 10분 유효합니다. 시도 번호를 확인해 이전 작업의 늦은 완료/실패가 재시도를 변경하지 못하게 합니다.
- Grounding HTTP 읽기 제한은 45초, 일정 작성은 100초입니다. 명시적 할당량 오류가 아닌 429와 503에만 지수 백오프로 최대 2회 재시도합니다. 재시도 시작 여유는 누적 15초이며 긴 Retry-After는 무시하지 않고 즉시 중단합니다. 시간 초과·네트워크 오류는 처리 여부가 불확실한 POST를 자동 재전송하지 않습니다. 생성 단계 사이에 240초 경과를 확인하지만 엄격한 전체 시간 강제 취소나 영속 작업 큐는 아직 아닙니다.
- 기존 일정 수 기반 쿼터는 해당 날짜 기록을 처음 만들 때만 전환 기준으로 사용합니다.
- 관리자 초기화는 기본 한도와 오늘 사용량을 충전하되 진행 중 예약은 보존합니다. 예전 채팅 쿼터 DTO 필드는 임시 호환용 0이며 사용하지 않습니다.

## 인증

OAuth 성공 URL에는 토큰 대신 90초짜리 단일 사용 코드를 전달합니다. 프론트는 같은 origin의 /api/auth/exchange로 교환합니다. Access JWT(30분)는 기존 프론트 호환을 위해 localStorage에 보관합니다. XSS에 대한 완전한 해결은 아니므로 CSP·메모리 보관 전환은 후속 보안 과제입니다.

Refresh는 무작위 불투명 문자열이며 DB에는 SHA-256 해시만 저장합니다. 브라우저에는 HttpOnly/Secure/SameSite=Lax 쿠키로 전달합니다. 갱신 시 기존 토큰을 소비하고 새 쿠키로 회전하며 절대 만료(14일)는 연장하지 않습니다. 로그아웃은 같은 family를 폐기합니다. 이미 발급한 Access는 만료 전까지 유효합니다.

Vercel rewrite가 인증 요청만 Render로 프록시하여 브라우저의 서드파티 쿠키 의존을 피합니다. 인증 POST는 허용 Origin을 반드시 확인합니다. 다른 API는 Bearer JWT를 사용합니다. 전체 OAuth/쿠키 경로의 실제 배포 검증은 남아 있습니다.

## 편집과 표시

모든 날짜를 일괄 전송합니다. 서버는 소유권·전체 날짜·중복 ID·지역·폐업·시간 충돌을 확인한 뒤 단일 트랜잭션으로 교체합니다. 클라이언트의 confidence/matchedBy/좌표를 검증 증거로 신뢰하지 않습니다. 목적지 ID가 없는 구버전 일정은 조회/삭제할 수 있지만 새 편집은 재생성이 필요합니다.

검증 UI는 장소 확인/확인 필요/미검증을 구분하고, Grounding 출처 링크를 추천 메모 옆에 표시합니다. 미래 영업 보장, 경로 검증, 정확도 100%로 표현하지 않습니다. 수동 교체의 저장 전 상태는 별도로 안내합니다.

## 데이터와 운영 제약

신규 인증·생성 상태에는 Flyway V1을 추가했습니다. 기존 도메인 스키마는 Hibernate update와 병행하므로 전체 스키마를 버전 관리하는 운영 완성형 마이그레이션은 아닙니다. 적용 전 DB 백업이 필요하며 적용된 Flyway 파일은 수정하지 않습니다.

일반 채팅 API·날씨 도구·회원가입 중복 화면·Redis/벡터 의존성·24시간 장소 원문 캐시는 제거했습니다. 기존 채팅/선호 테이블과 예전 EC2 Compose는 데이터 파괴를 피하려고 남겨뒀습니다.

실제 도로 이동/대중교통 가능성, 임시 휴무, 예약, 접근성은 보장하지 않습니다. 동선 묶기·알레르기 등 자유 요청은 AI에 전달하는 선호이지 안전 보증이 아닙니다. 여러 도시·가족/어르신 조건의 품질 평가와 API 비용 측정이 후속 과제입니다.
