# 🧭 Compass: AI 기반 개인화 여행 에이전트 기술 설계 가이드

## 1. 프로젝트 개요 (Introduction)
**Compass**는 단순한 여행 일정 생성기를 넘어, 사용자의 **암묵적 취향을 기억(Memory)**하고 **실시간 외부 데이터(Action)**를 결합하여 최적화된 여행 경로를 제안하는 **컨텍스트 인지형(Context-Aware) AI 에이전트**입니다.

### 핵심 가치
* **지능형 개인화 (Hyper-Personalization)**: 사용자의 과거 대화와 성향을 벡터 데이터화하여 맞춤형 추천을 수행합니다.
* **신뢰성 확보 (Reliability)**: Function Calling 메커니즘을 통해 AI가 실제 검증된 장소 정보와 좌표를 기반으로 일정을 설계하도록 제어합니다.
* **유연한 확장성 (Agility)**: Spring AI 추상화 레이어를 활용하여 모델(Gemini, Claude 등)의 교체와 도구 추가가 용이한 구조를 유지합니다.

---

## 2. 시스템 아키텍처 (System Architecture)

본 시스템은 단순 요청-응답 구조를 탈피하여, AI가 판단의 주체가 되는 **AI 오케스트레이션(AI Orchestration)** 레이어를 중심으로 설계되었습니다.

### 주요 레이어 및 흐름
1.  **Request Layer**: 사용자로부터 자연어 기반의 여행 계획 요청을 수신합니다.
2.  **Orchestration Layer (`TravelAgentService`)**: 요청을 분석하고, 필요한 개인화 컨텍스트와 외부 툴을 오케스트레이션합니다.
3.  **Context Layer (RAG)**: `pgvector` 기반의 벡터 검색을 통해 사용자의 과거 선호도와 장소 데이터를 동적으로 프롬프트에 주입합니다.
4.  **Action Layer (Function Calling)**: 실시간 장소 검색 API를 호출하여 위도, 경도 및 운영 정보 등 실제 데이터를 확보합니다.
5.  **Execution Layer**: 모든 데이터를 종합하여 구조화된 JSON 형태로 최종 플랜을 생성합니다.

## 3. 핵심 기술 스택 (Tech Stack)

### Backend & AI
* **Language**: Java 17
* **Framework**: Spring Boot 3.4.1
* **AI Framework**: Spring AI
* **LLM**: Gemini 2.0 Flash (Long Context Window 활용)

### Data & Storage
* **RDBMS**: PostgreSQL 15 + **pgvector** (벡터 임베딩 검색)
* **Cache**: Redis (대화 문맥 유지)
* **Flexible Data**: JSONB 필드를 활용하여 유연한 데이터 스키마 유지

---

## 4. 엔지니어링 디테일 (Engineering Excellence)

### 4.1 구조화된 출력 (Structured Output)
AI의 응답을 예측 가능한 모델로 변환하기 위해 엄격한 JSON 스키마를 프롬프트에 정의하여, 백엔드 로직과의 데이터 정합성을 보장합니다.

### 4.2 컨텍스트 인지형 대화 관리
`ChatSession`과 `ChatMessage`를 통해 대화 이력을 추적하며, 사용자 고유의 선호도(Preference)를 실시간으로 반영합니다.

### 4.3 AI 증강 개발 (AI-Augmented Development)
설계 단계부터 AI와의 페어 프로그래밍을 적극 활용하여 도메인 모델링(User, Trip, Place 등) 및 인프라 구축(Docker, CI/CD) 속도를 혁신적으로 단축했습니다.

## 5. 로드맵 및 확장 계획 (Roadmap)

* **RAG 고도화**: 단순 취향 저장을 넘어, 벡터 데이터 기반의 유사 장소 추천 로직 구현.
* **Multi-Tool 연동**: 구글 지도 API 외 날씨, 교통 정보 등 다양한 외부 API를 에이전트가 직접 제어하도록 확장.
* **배포 자동화**: GitHub Actions 기반의 AWS 배포 파이프라인 완성.
